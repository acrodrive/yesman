# 10단계. 제안 방법 학습 (Ours) (2026-10-07)

yesman.md 11절 10단계의 결과와 계획서와 달라진 점을 정리한 것이다. GPU pod(RTX 5090)에서 수행하였다.

## 사전 결정 (결과를 보기 전)

- 보이지 않는 원인 CF⁻(학습 묶음 631개, 검증 71개)는 학습과 검증에서 뺀다 (사용자, 2026-10-07). 학습 데이터는 1.0%, CF⁻는 7.6% 줄어든다(다른 차·보행자 기준은 3,053 → 2,422).
- 학습 설정은 9단계 비교 모델과 같다(디코더, 20,000 step, batch 256, 최적화, 시드 0과 1). 판단 토큰과 head를 켠다(8단계 구조).
- 샘플 비율: 원래 결정과 CF⁺는 B-순응과 같은 비율로 뽑고, CF⁻는 전체 무게가 CF⁺와 같도록(CF⁺ : CF⁻ = 1 : 1, 14절) 더 자주 뽑는다. batch 안의 비율은 원래 0.238 : CF⁺ 0.381 : CF⁻ 0.381이다(CF⁻ 한 개가 평균 약 4번 뽑힌다).
- 목표(8.4): 원래 결정 = 사람 경로, CF⁺ = L2 경로, CF⁻ = 사람 경로 + REJECT + 판단 근거. 손실 = 경로 L1 + flag BCE + 근거 BCE(REJECT 샘플만), 가중치는 모두 1.
- flag 기준값 τ (14절 예시값): 검증 세트에서 청개구리 비율(원래 결정 + CF⁺를 거부한 비율)이 5% 이하가 되는 가장 큰 값. p < τ이면 REJECT.
- S2 "크게 떨어지지 않는다"의 기준: D0 EPDMS가 B2보다 0.02를 넘게 떨어지지 않는다(B2와 B-순응의 차이 정도).

- **p가 거의 0 또는 1로 몰린다.** τ가 0.9999 근처인 것은 이 때문이다. 판단 head가 학습 CF⁻(7,724개를 약 4번씩 본다)를 외워 손실이 거의 0이 되었다. 검증 AUC는 5천 step 0.974 → 2만 step 0.968로 거의 변하지 않으므로 일반화에는 큰 영향이 없다. Figure 1의 곡선은 p 대신 logit으로 기준값을 바꾸어 그리면 된다.
- 500 step만 학습해도 검증 AUC가 0.97이었다. CF⁻가 결정 모양만으로 쉽게 구분될 수 있다는 신호이다(계획서 13.4 "counterfactual decision이 쉬울 수 있다"). 11단계에서 불가능 기준별로 확인한다.

## D0, D1 (navtest, τ 적용)

| D0 EPDMS | 0.861 | 0.855 |
| D0 따르기 / 언행 불일치 / 청개구리 | 84.0% / 11.0% / 5.0% | 84.9% / 11.8% / 3.2% |
| D1 따르기 / 언행 불일치 / 청개구리 | 46.4% / 41.5% / 12.1% | 44.8% / 45.1% / 10.1% |

- navtest D1의 청개구리 비율(10~12%)이 검증 세트 기준(5%)보다 높다. D1은 장면마다 CF 메뉴 전부이고 검증 세트는 장면마다 4개를 무작위로 뽑았으므로, 결정 종류의 구성이 다르다.

## 비교 모델과 함께 (D1 따르기, flag 무시)

| 모델 | D0 EPDMS | D1 따르기 | offset·차선 변경 4종 평균 | faster·slower·stop 평균 | 회전 4종 평균 | 검증 CF⁺ 따르기 |
| --- | --- | --- | --- | --- | --- | --- |
| B2 (0 / 1) | 0.880 / 0.878 | 0.353 / 0.356 | 0.03 / 0.03 | 0.69 / 0.68 | 0.74 / 0.81 | 0.359 / 0.359 |
| B-순응 | 0.862 / 0.854 | 0.553 / 0.546 | 0.43 / 0.43 | 0.72 / 0.68 | 0.65 / 0.66 | 0.620 / 0.624 |
| Ours | 0.861 / 0.855 | 0.491 / 0.468 | 0.36 / 0.34 | 0.66 / 0.62 | **0.43 / 0.42** | 0.565 / 0.537 |

- **Ours는 B-순응보다 CF⁺를 덜 따른다**(검증 CF⁺ 62% → 54~57%, navtest D1 55% → 47~49%). 특히 회전(65% → 42%)이 크게 낮다. CF⁻의 대부분이 회전과 차선 변경이고(6단계) CF⁻의 목표 경로는 사람 경로이므로, 회전 결정을 실행 가능할 때에도 덜 따르게 된 것으로 보인다. 계획서 13.5의 "CF⁻ 학습 때문에 결정을 무시하는 버릇"이 일부 나타났다. 13.5의 대응은 "CF⁺와 CF⁻의 비율을 조절한다"이다.
- D0 점수는 B-순응과 같다. S2의 하락은 CF⁻나 판단 head가 아니라 CF⁺ 학습(B-순응과 공통)에서 온 것으로 보인다.

## 계획서와 달라진 점

1. 보이지 않는 원인 CF⁻를 학습에서 뺐다(사용자 결정).
2. CF⁻를 더 자주 뽑아 CF⁺ : CF⁻ = 1 : 1로 맞추었다(14절의 시작값). 학습 묶음 자체는 약 4 : 1이다.
3. 9단계와 같이 학습 batch를 뽑는 코드를 `torch.randint`에서 무게를 준 `torch.multinomial`로 바꾸었다. B1, B2, B-순응은 무게가 모두 같아 분포는 같다(같은 시드로 다시 돌리면 뽑는 순서는 다르다).
