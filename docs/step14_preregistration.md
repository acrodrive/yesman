# 14단계. 성능 개량과 새 테스트 세트에서의 확인 — 사전 등록

> **상태: 고정 (2026-10-14).** 이 문서를 커밋한 시점이 고정 시점이다. 고정할 때 정한 것은 10절에 모았다. 고정한 뒤에는 결과를 보고 바꾸지 않는다. 바꿔야 하면 바꾼 이유와 바꾸기 전 기준의 결과를 함께 기록한다.

이 문서는 13단계 이후에 하는 성능 개량 실험을, 결과를 보기 전에 정해 두는 문서이다. 용어와 모델 이름은 `docs/TODO.md`의 A-1, A-2를 따른다. 할 일 목록과 그 근거는 `docs/TODO.md`에 있다.

## 1. 왜 이 단계를 하는가

### 1.1. 기존 Ours의 문제

기존 Ours(이 문서의 이전 Ours)는 판단 head와 경로를 만드는 DiT가 장면 토큰과 결정 토큰을 각각 받아 **병렬로** 계산하는 구조였다. 판단 head는 DiT가 경로를 만드는 과정을 보지 못하므로, 판단과 경로가 서로 다른 맥락에서 나왔다. 실제로 판단 head가 "따른다"고 확신했는데 경로는 결정을 따르지 않은 경우가 32%였다. 또 판단 head를 뺀 모델(B3)과 불가능한 결정의 안전율이 같았다(75.8% 대 76.2%). 안전은 판단 head가 아니라 CF⁻ 학습에서 왔다.

처음에 병렬 구조를 택한 이유는 diffusion의 랜덤성이었다. 같은 결정이 시작 노이즈에 따라 실행마다 다르게 판단되는 것을 결함으로 보고, 판단을 노이즈와 무관하게 분리했다. 그러나 경계 상황에서 판단이 흔들리는 것은 사람 운전자도 마찬가지이다. 같은 상황에서도 어떤 날은 끼어들고 어떤 날은 끼어들지 않는다. 위험한 것은 흔들림이 아니라 판단과 행동이 어긋나는 것이다.

그래서 새 Ours는 판단을 DiT가 경로를 만드는 내부 표현에서 읽는다. 12단계 D에서, 학습이 끝난 DiT의 내부 표현에서 판단을 읽었을 때(probe) 처음 보는 VLM(Gemma 4 31B)의 틀린 결정을 가르는 AUC가 0.67에서 0.80으로 올랐다. 새 Ours는 이것을 사후 분석이 아니라 모델의 정식 구조로 만든다.

### 1.2. 학습 CF의 문제

규칙 기반 CF⁻(정해진 메뉴로 만든 실행 불가능한 결정)로 잰 효과는 실제 VLM의 틀린 결정에서 절반 이하로 줄었다(규칙 기반 CF⁻ 77% → 실제 VLM 36~43%). 규칙 기반 CF⁻는 보면 바로 틀린 결정이 많았고, 실제 VLM의 틀린 결정은 그럴싸하지만 움직임 때문에 틀리는 결정(앞차가 가까운데 속도를 높이는 결정 등)이 많았다. 12단계 C에서 plausible CF⁻(닮은 장면이나 조금 전에 사람이 한 결정)를 넣자, VLM을 쓰지 않고도 처음 보는 VLM 3개 중 2개에서 안전율이 12~13%p 올랐다. 12단계 A의 확장된 규칙 기반 CF(W)도 비슷한 효과를 냈다.

그래서 이 단계의 성능 개량은 **질 좋은 CF를 많이 두고, CF⁺와 CF⁻의 분량을 조절하는 것**이다.

### 1.3. navtest는 개발 세트가 되었다

11단계에서 navtest의 D2, D3를 본 뒤, 12단계의 실험 방향과 최종 모델 교체(목표 경로를 사람 경로를 고친 경로로 바꾼 모델로 교체)를 navtest 결과를 보며 정하였다. 따라서 navtest는 더 이상 깨끗한 테스트 세트가 아니다. 이 단계부터 navtest는 **개발 세트**로 부르고, 처음 보는 데이터로 새 테스트 세트를 만든다. 새 Ours의 설계도 navtest에서 기존 Ours를 분석하다 나온 것이므로, 확인은 새 테스트 세트에서 한다.

## 2. 데이터

### 2.1. 데이터 나누기

navtrain 카메라 데이터는 32조각이고, 2단계에서 8조각(1, 5, 9, 13, 17, 21, 25, 29번)만 받았다. 남은 24조각을 모두 받아 다음과 같이 나눈다. 조각은 로그 순서로 나뉘어 있으므로, 도시가 치우치지 않도록 용도마다 번호를 고르게 섞는다.

| 용도 | 조각 | 장면 수(추정) | 규칙 |
| --- | --- | --- | --- |
| 기존 학습 | 1, 5, 9, 13, 17, 21, 25, 29 | 23,388 | 학습 로그 274개, 검증 로그 30개(`data_lists/navtrain_sensor_val_logs.txt`)로 이미 나뉨 |
| **테스트** | 3, 11, 19, 27 | 약 1.2만 | 체크섬으로 고정하고 한 번만 평가한다 |
| **예비** | 7, 15, 23, 31 | 약 1.2만 | 받아 두되 결과를 보지 않는다. 이 단계의 결과를 보고 무언가를 바꿨을 때 다음 라운드의 확인에 쓴다 |
| **학습 추가** | 나머지 16조각 (2, 4, 6, …, 32) | 약 4.7만 | 학습 장면을 약 2.3만에서 약 7만으로 늘린다 |

- 조각 번호는 1~32이다(`scripts/data/download_navsim.sh`). 나누기는 `scripts/step14_shards.py`의 GROUPS에 같은 값으로 적혀 있고, 로그 겹침이 있으면 멈춘다.
- 학습 추가 조각에서도 로그의 10%를 검증으로 뗀다(시드 0, `scripts/step14_shards.py --extra_val_frac 0.1`). 검증 세트 = 기존 30개 로그 + 추가 로그의 10%.
- 테스트, 예비 조각의 로그가 학습·검증 로그와 겹치지 않는지 확인하고, 같은 도시·날짜가 겹치는 정도를 기록한다.
- 알려진 누설: L2 경로 모음과 L1 기준값은 navtrain 로그 전체(이 조각들 포함)로 만들었다. L2는 판정할 장면과 같은 로그의 경로를 후보에서 빼므로 판정에는 문제가 없다. 한계로 기록한다.

### 2.2. 새 테스트 세트의 구성

| 세트 | 내용 |
| --- | --- |
| D0 | 사람의 원래 결정 |
| D1 | 실행 가능한 CF(CF⁺). 장면마다 규칙 기반 CF 메뉴 전부를 L2로 판정한 결과 |
| D2 | 실행 불가능한 CF(CF⁻). 위와 같음 |
| **D3 (주 대상)** | **Gemma 4 31B**(QAT 4비트, 7단계·12단계와 같은 프롬프트, JSON 스키마, greedy 디코딩)를 테스트 장면 전체에 돌린 결정. L2로 판정 |
| D3 보조 | 시간이 되면 Qwen3-VL 8B를 같은 방식으로 추가 |

- 새 모델들은 VLM 출력 기반 CF로 학습하지 않으므로, D3의 VLM은 모두 **처음 보는 VLM**이다.
- 표본 수 예상: navtest에서 Gemma 4 31B의 실행 불가능한 결정은 약 3%(3,000장면 중 94개)였다. 테스트 약 1.2만 장면이면 약 370개이고, 불가능한 결정의 안전율의 95% 구간은 대략 ±5%p로 예상한다.
- 장면 목록, 각 세트의 parquet, 체크섬을 만든 뒤 고정한다. **고정하기 전에도, 고정한 뒤에도 모델 결과를 보지 않는다.**

## 3. 비교 모델

비교 모델은 구성 요소를 하나씩 더해 가는 사다리로 둔다.

| 이름 | 코드 실행 이름 (현행) | 학습 데이터 / 구조 | 더한 것 |
| --- | --- | --- | --- |
| B0 | `B1_seed*` | 결정을 입력으로 받지 않음 | 비교 기준. 결정을 쓰지 않는 기존 방식의 planner |
| B1 | `B2_seed*` | 결정 입력, 원래 결정만 학습 | 결정 입력 |
| B2 | `Bcomply_*` | + CF⁺ | 실행 가능한 결정을 따르는 법 |
| B3 | `B3_*` | + CF⁻, 판단 head 없음 | 실행 불가능한 결정을 피하는 법 |
| **Ours (주 모델)** | `OursDiT_*` (새로 만듦) | + 판단 head를 DiT 내부 표현에서 분기 | 거부 표시. 판단과 경로가 같은 표현에서 나옴 |
| 이전 Ours (ablation) | `Ours_*` (기존) | Ours와 같되, 판단 head가 DiT와 **병렬** | 사다리 밖. 판단을 읽는 위치만 다른 비교 대상 |

- **주 모델은 Ours이다.** 테스트 결과를 보고 바꾸지 않는다. 결과가 기대와 달라도 그대로 보고한다.
- **이전 Ours**는 13단계까지의 Ours(초안의 B4)이다. 지금까지의 결론(9~13단계)이 이 모델로 나왔으므로 지우지 않고, 사다리에서 빼서 Ours의 ablation으로 남긴다. 새 구조의 핵심 주장("판단을 DiT 안에서 읽으면 판단과 경로가 더 잘 맞는다")은 이 모델과의 비교로만 확인할 수 있다. CF 학습 구성은 따로 고르지 않고 Ours가 고른 구성을 그대로 쓴다(4.6절). 그래서 두 모델은 판단을 읽는 위치만 다르다.
- 모든 모델은 1단계(4.1절)로 늘린 데이터로 다시 학습하고, 시드 0과 1로 학습한다.
- 코드 실행 이름은 바꾸지 않는다. 같은 "B1"이 문서와 코드에서 다른 모델을 가리키므로, 보고서와 README에 위 대응표를 싣는다.

## 4. 성능 개량: CF 학습 구성

질 좋은 CF를 많이 두고 CF⁺와 CF⁻의 분량을 조절한다. 후보를 전부 곱하면 수십 가지가 되므로 **양 → 질 → 비율 순서로** 단계적으로 정한다. 앞 단계에서 정한 것을 고정하고 다음 단계로 간다. 고르는 일은 모두 **검증 세트**로 하고, 고를 때는 시드 0 하나로 학습한다.

- **VLM 출력 기반 CF는 학습에 쓰지 않는다.** 12단계 A에서 VLM 출력 기반 CF는 학습에 쓴 VLM에만 효과가 있었고, 처음 보는 VLM으로는 옮겨 가지 않았다. VLM의 오류 유형을 직접 학습하지 않고, plausible CF와 확장된 규칙 기반 CF로 그럴싸한 오답을 만든다.
- **터무니없는 CF⁻도 없애지 않는다.** 12단계 C에서 그 비중을 15%로 줄였더니 도로 기준 안전율(불가능한 이유가 도로 모양인 결정에서의 안전율)이 떨어졌다(Gemma 4 31B 73 → 55%).

### 4.1. 1단계: 양 늘리기

고르는 단계가 아니라, 늘린 뒤 고정하는 단계이다.

| | 내용 | 근거 |
| --- | --- | --- |
| (a) | 학습 장면마다 규칙 기반 CF 메뉴 **전부**를 판정한다 | 지금은 시간 때문에 장면마다 최대 12개 중 4개만 판정했다. 전부 판정하면 CF가 약 3배 |
| (b) | **plausible CF⁺**도 학습에 넣는다 | 12단계 C는 plausible CF 중 실행 불가능한 것만 CF⁻로 쓰고, 실행 가능한 것은 버렸다. 실행 가능한 plausible CF는 질 좋은 CF⁺이다 |
| (c) | **확장된 규칙 기반 CF(W)**를 넣는다(장면마다 4개) | VLM을 쓰지 않고 만든 CF로, 처음 보는 VLM 3개에서 안전율을 올렸다(Gemma 4 31B 35.6 → 39.4%, Gemma 4 12B 37.0 → 44.9%, Qwen3-VL 8B 43.0 → 60.3%). plausible CF와 잘하는 곳이 달라 보완 관계로 본다 |
| (d) | **학습 장면을 늘린다**(학습 추가 16조각, 약 2.3만 → 약 7만 장면) | 앞차가 가까운 장면처럼 드문 상황의 예가 늘고, plausible CF가 닮은 장면을 찾는 후보도 늘어난다 |

- CF⁺의 target 경로는 기존과 같은 방식으로 만든다. 그 장면 사람 경로에서 결정이 바꾸라는 부분(속도 또는 옆 거리)만 고치고, 고친 경로가 결정과 맞지 않거나 안전 확인을 통과하지 못하면 L2를 통과한 다른 장면의 사람 경로 중 이 장면 사람 경로와 가장 가까운 것을 쓴다.
- 장면 수의 효과는 시험한 적이 없다. 무엇이 성능을 올렸는지 설명할 수 있게, 장면 수를 단계적으로 늘린 결과를 검증 세트로 잰다. **이 비교는 고르는 것이 아니라 보고만 한다. 최종 모델은 언제나 +16조각을 쓴다.**
  - 단계: 0(기존 8조각, (a)(b)(c)만) / +4 / +8 / +16조각. 앞 단계를 포함하도록 늘리고(+8은 +4를 포함), 조각 번호는 도시가 치우치지 않도록 고르게 퍼뜨린다.
    - +4: 2, 10, 18, 26
    - +8: +4에 6, 14, 22, 30 추가
    - +16: 학습 추가 조각 전부
  - 모델: B3, 시드 0, 4.2절에서 고른 step 수와 크기, 2단계 이전의 기본 구성. `train_planner.py --extra_shards`로 학습 장면만 줄이고 검증 세트는 모든 단계에서 같다.
  - 재는 값: 4.2절과 같다(검증 세트의 결정–경로 일치율, 불가능한 결정의 안전율, 둘의 평균).
  - 한계로 기록한다: plausible CF는 닮은 장면을 전체 학습 조각에서 찾으므로 작은 단계의 CF에도 추가 조각의 정보가 들어 있다. step 수는 +16 데이터로 고르므로 작은 단계는 같은 step에서 과적합할 수 있다.

### 4.2. 학습 step 수와 모델 크기 다시 정하기

지금의 20,000 step(batch 256)은 지금 데이터 크기에서 검증 세트로 고른 값이다. 1단계로 데이터가 3배 이상 늘면 같은 step으로는 장면마다 보는 횟수가 3분의 1로 줄어 학습이 덜 될 수 있다. 반대로 너무 오래 학습하면 검증 오차가 다시 오른다(9단계에서 2.5만 step 이후). 그래서 1단계를 고정한 직후, 2단계 전에 다시 고른다.

- **step 수마다 따로 학습한다.** 학습률이 마지막 step까지 줄어드는 방식(cosine)이므로, 긴 학습의 중간 지점은 처음부터 그 step 수로 학습한 모델과 다르다.
- 후보: **20,000 / 40,000 / 80,000 / 120,000 step**
- 모델: **B3** (결정 입력, CF⁺, CF⁻를 모두 쓰는 모델이라 대표로 쓴다), 1단계 데이터, 2단계 이전의 기본 구성, 시드 0
- 재는 값: 검증 세트의 결정–경로 일치율(CF⁺)과 불가능한 결정의 안전율(CF⁻), 둘의 평균
- 고르는 규칙: 평균이 가장 좋은 후보와 차이가 0.01 이내인 후보 중 **가장 짧은 것**
- **모델 크기**: 고른 step 수에서 디코더 **층 4(지금) / 층 6 / 폭 384**(FFN 1,536)를 B3로 비교하고, 같은 평균이 지금 크기보다 **0.01 넘게 좋을 때만** 큰 쪽을 쓴다(둘 다 넘으면 더 좋은 쪽). 파라미터는 4.5M / 6.6M / 10.1M이다(`train_planner.py --n_layers 6`, `--d_model 384`). 층을 늘리면 여러 정보를 엮는 단계가 늘고(강도·거리 판단처럼 앞차 거리, 내 속도, 결정 강도를 함께 봐야 하는 문제), 폭을 늘리면 한 번에 담는 특징이 늘어난다(장면이 다양해진 데이터)
- 참고로 함께 기록한다: 학습 데이터에서의 결정–경로 일치율. 크기를 키워도 이 값이 오르지 않으면 용량은 병목이 아니다
- 고른 step 수와 크기는 모든 모델(B0~B3, Ours, 이전 Ours)에 같게 쓴다
- 비용: step 하나의 시간은 데이터 크기와 무관하다(2만 step에 약 4분, 9단계 기록). 후보 4개와 크기 비교 2개를 합쳐 약 1~2시간

### 4.3. 2단계: 질 조합 고르기

목표는 강도·거리 판단 실패의 주 원인인 **강도 기준 CF⁻ 부족**(지금 학습 묶음에 452개, 배치의 약 0.8%)을 메우고, 결정 종류만 보고 맞히는 지름길을 막는 것이다.

| 장치 | 후보 | 설명 |
| --- | --- | --- |
| plausible CF⁻ 비중 | 0.4 / 0.6 / 0.85 | CF⁻ 안에서 plausible CF⁻가 차지하는 무게 |
| 강도 기준 CF⁻ 무게 | 끔 / 켬 | CF⁻ 안에서 강도 기준 CF⁻의 무게를 도로 기준과 같게 올린다(`train_planner.py --balance_strength`) |
| 결정 종류별 가능/불가능 균형 | 끔 / 켬 | 결정 종류마다 CF⁺와 CF⁻의 무게를 맞춘다. 지금은 회전 CF의 약 76~84%가 실행 불가능이라, 장면을 보지 않고 "회전이면 거부"만 배워도 대부분 맞는다 |
| plausibility 가중치 | 끔 / 켬 | CF⁻가 학습에 뽑히는 가중치를 그럴싸함 점수(6절)에 비례해 준다. 가중치 = max(점수, min 값), min 값 = 0.05. 점수가 0인 터무니없는 CF⁻도 없애지 않기 위해서이다(12단계 C에서 줄였더니 도로 기준 안전율이 떨어졌다). 점수는 **강도까지 같은 비율**을 쓴다(`--plaus_weight strength`). 행동 종류만 같은 비율로는 "앞차가 가까운데 세게 가속"과 "살짝 가속"이 같은 점수를 받아, 이 단계의 목표인 강도 기준 CF⁻를 가르지 못한다 |

고르는 순서:
1. plausible CF⁻ 비중 3개를 학습해 하나를 고른다(나머지 장치는 끔).
2. 고른 비중 위에 나머지 세 장치를 하나씩 켜 보고, 점수가 오르면 켠 채로 다음 장치로 간다.
3. 모두 6번 학습한다.

### 4.4. 3단계: CF⁺ : CF⁻ 비율 고르기

지금은 CF⁻ 전체 무게가 CF⁺의 0.25배이다(10단계에서 1 / 0.5 / 0.25 중 고름). 1·2단계로 CF의 양과 질이 바뀌었으므로 다시 고른다. 후보: **0.25 / 0.5 / 1**.

### 4.5. 고르는 규칙: 상한선에 가장 가까운 구성

CF⁻를 세게 학습할수록 실행 불가능한 결정에는 안전해지지만, 실행 가능한 결정도 덜 따르게 된다. 이 trade-off에서 상한선에 가장 가까운 구성을 고른다. 상한선은 판단을 완벽하게 하는 가상의 모델이다. 실행 가능한 결정은 결정만 따르도록 학습한 모델(B2)만큼 따르고, 실행 불가능한 결정은 전부 거부하고 결정을 무시한 경로(B0)로 달린다.

```
점수 = ½ × (D1 결정–경로 일치율 / B2의 D1 결정–경로 일치율)
     + ½ × (불가능한 결정의 안전율 / B0의 불가능한 결정의 안전율)
```

- 두 값은 모두 검증 세트에서 잰다. 상한선(B2, B0의 값)은 1단계로 늘린 데이터로 학습한 B2, B0로 잰다.
- 한쪽만 높이는 구성(예: 결정을 다 거부해서 안전율만 높은 구성)은 다른 쪽이 깎여 점수가 낮아진다.
- 두 축의 무게는 ½, ½로 한다.
- 2단계와 3단계 모두 이 규칙을 쓴다.

### 4.6. 모델마다 따로 고르기

핵심 비교는 B3와 Ours이다. Ours에 맞춰 고른 구성을 B3에 그대로 쓰면, B3는 자기에게 최적이 아닌 구성으로 학습된 셈이고, 이 불공정은 테스트로 드러나지 않는다. 그래서 **B3와 Ours는 4.3~4.5절의 절차를 각자 따로 거친다.** B1, B2는 CF⁻를 쓰지 않으므로 고를 구성이 없다. B2는 1단계로 늘린 CF⁺를 그대로 쓴다.

**이전 Ours는 구성을 따로 고르지 않고 Ours가 고른 구성을 그대로 쓴다.** 이 모델은 판단을 읽는 위치의 효과를 보는 ablation이므로 판단 위치 말고는 Ours와 같아야 한다. 이전 Ours의 판단 head는 경로에 영향을 주지 않고 CF 구성은 경로로 고르므로, Ours의 구성을 빌려 써서 이전 Ours가 불리해질 뚜렷한 이유는 없다. 그래도 Ours에 맞춘 구성이라는 점은 한계로 기록한다.

비용 추정: 모델 하나의 학습은 지금 약 4분이고, 데이터가 3배면 약 12분이다. 후보가 약 9개(2단계 6 + 3단계 3)이므로 모델 하나에 약 2시간, 두 모델에 약 4시간이다.

## 5. 새 Ours의 구조

### 5.1. 구조

- DiT는 지금처럼 장면 벡터와 결정을 받아 내부 연산을 하고 waypoint를 낸다. **DiT는 한 번만 돌리고, 최종 경로는 그 DiT의 waypoint 출력이다.**
- waypoint가 나오기 전 적절한 위치에서 DiT 내부 표현을 분기해 head로 열고, 판단(ACCEPT / REJECT)과 사유(충돌 / 도로 이탈 / 역주행)를 읽는다.
- 판단의 뜻: ACCEPT는 이 장면에서 4초 안에 충돌, 도로 이탈, 역주행 없이 실행할 수 있는 결정이다. REJECT는 실행하면 이 셋 중 하나를 피할 수 없는 결정이다. 정답은 L2 판정이다.
- 실행 불가능한 결정의 target 경로는 사람 경로이므로, DiT는 그런 결정을 받으면 결정을 피해 그리도록 학습된다. 그래서 REJECT일 때 내부 표현에는 결정을 피하는 경로의 표현이 이미 들어 있어야 하고, 판단과 경로가 같은 맥락을 갖는다.
- 판단과 경로의 일치는 구조로 강제한 것이 아니므로 보장되지 않는다. 같은 표현을 공유해 높아질 것으로 기대하는 값이며, 측정해서 보여 줄 결과이다.

### 5.2. Ours만의 설정

CF 학습 구성(4절)을 고르는 동안에는 아래 기본값을 쓴다. 구성을 고른 뒤, Ours만 따로 아래 후보를 고른다.

| 설정 | 기본값 | 후보 | 고르는 규칙 |
| --- | --- | --- | --- |
| ① 분기 위치 | 마지막 층, 노이즈 제거 마지막 단계 (12단계 D와 같음) | 마지막 층으로 한다. 검증 세트에서 결정 종류 안 AUC가 이전 Ours보다 낮으면 중간 층(2층)도 학습해 고른다 | 아래 "판단 설정을 고르는 규칙" |
| ② 학습 방식 | DiT와 head를 함께 학습 | 함께 학습 / DiT를 먼저 학습하고 고정한 뒤 head만 학습 | 아래 "판단 설정을 고르는 규칙" |
| ②' 판단을 학습할 노이즈 단계 | t < 100 | 고르지 않는다 (t < 100 고정) | 아래 |
| ③ 노이즈 투표 | K = 1 | K = 10, m = 1 / 2 / 3 / 5 | 아래 |

- **판단 설정을 고르는 규칙 (①②)**: 후보 중 검증 세트의 **결정 종류 안 AUC**가 가장 높은 것을 고른다. 단 4.5절의 점수가 기본 설정(마지막 층, 함께 학습)보다 0.01 넘게 낮은 후보는 뺀다(`select_config.py --rule auc --base <기본 설정>`). ①을 먼저 정하고, 고른 분기 위치에서 ②를 정한다. ①에서 비교할 이전 Ours는 Ours가 고른 CF 학습 구성으로 시드 0을 학습한 모델이다.
  - 4.5절의 점수로 고르지 않는 이유: 노이즈 1개일 때 Ours의 경로는 판단과 상관없는 DiT 출력이다. 4.5절 점수의 안전율은 경로만 보고, 일치율은 판단을 보지만 τ를 "실행 가능한 결정의 5%까지 거부"로 맞추므로 어떤 판단이든 거의 똑같이 깎인다. 그래서 경로가 같으면 판단이 좋은 모델과 나쁜 모델의 점수가 같다. ①②는 판단을 좋게 하려는 설정이므로 판단을 직접 재는 AUC로 고른다. 4.5절 점수는 판단 학습이 경로를 해치지 않았는지 확인하는 데만 쓴다(②의 함께 학습은 판단 손실이 DiT 경로도 바꾼다).
- **판단을 학습할 노이즈 단계**: DiT는 노이즈 단계 t(0~999)를 무작위로 뽑아 학습하지만, 판단은 샘플링의 마지막 단계(t = 0)에서 읽는다. 노이즈가 많은 단계의 표현에는 경로 정보가 적으므로, 판단 손실은 노이즈가 적은 단계(t < judge_t_max)의 표현으로만 계산한다. 그래서 판단은 "지금 그리고 있는 경로"의 표현을 보고 나온다. **t < 100으로 고정한다.** 샘플링은 10단계 DDIM(t = 999, 888, …, 111, 0)이고 판단은 t = 0에서만 읽으므로, 이 값은 학습 때의 노이즈 범위만 바꾼다. 효과가 작을 것으로 보아 후보를 두지 않는다.
- 구현: `yesman/model.py`(`judge_from = "dit"`, `judge_layer`, `judge_t_max`, `judge_detach`, `Planner.sample_vote`), `scripts/train_planner.py --model OursDiT [--judge_layer] [--judge_t_max] [--freeze_dit --init_from <DiT를 학습한 실행>]`, `scripts/predict_planner.py --vote_k K --vote_m M --tau τ`. 단위 테스트 `tests/test_model.py`(가짜 텐서, CPU).
- **판단 기준값**: 노이즈 하나일 때 판단 확률의 기준값 τ는 지금처럼 "검증 세트에서 실행 가능한 결정을 거부하는 비율이 5% 이하"가 되도록 정한다.
- **노이즈 투표**: 같은 입력에 시작 노이즈 K개로 DiT를 한 배치로 돌리고, REJECT가 m개 이상이면 거부한다. 최종 경로는 최종 판단과 같은 판단을 낸 샘플 중에서 고른다(거부면 REJECT를 낸 샘플의 경로, 아니면 ACCEPT를 낸 샘플의 경로). 그중 그 판단의 확신이 가장 큰 샘플을 고른다(거부면 p가 가장 낮은 샘플, 아니면 p가 가장 높은 샘플).
- **m 고르는 규칙**: 검증 세트에서 실행 가능한 결정을 거부하는 비율이 5% 이하인 m 중, 불가능한 결정의 안전율이 가장 높은 것.
- **K = 10으로 고정한다.** 디코더가 작아 투표의 지연이 크지 않다(맥 CPU, 가중치 없는 새 Ours: 노이즈 1개 22 ms, 10개 56 ms). 그래서 지연으로 K를 고르지 않는다. pod에서 K = 1, 5, 10의 지연을 재어 보고한다(`scripts/measure_latency.py`).

## 6. 그럴싸함 점수

CF⁻가 얼마나 그럴싸한지를 출처(규칙 기반 / plausible)가 아니라 점수로 잰다. 4.3절의 plausibility 가중치와 결과 분석에 쓴다.

- 정의: 장면 S의 결정 d에 대해, 다른 로그에서 내비게이션 명령이 같고 속도 차이가 2 m/s 이내인 장면 중 LTF 장면 특징의 cosine 유사도가 가장 높은 K개 장면에서, 사람이 한 결정이 d와 같은 비율.
- 두 가지를 저장한다: 행동 종류만 같은 비율 / 강도까지 같은 비율(±0.2).
- K = 50. plausible CF⁻는 상위 10개 장면의 사람 결정으로 만들었으므로, 그 CF⁻를 만든 원천 장면은 이웃에서 뺀다(순환 방지. 빼지 않으면 plausible CF⁻는 점수가 언제나 0.02 이상이 된다). `scripts/cf_plausibility.py --k 50`, 원천 장면은 `src_token` 열.
- 분석에 쓰는 구간: 0 / 0 초과 0.1 미만 / 0.1 이상. K = 50에서 각각 이웃 0개 / 1~4개 / 5개 이상이다.
- 4.3절의 plausibility 가중치는 강도까지 같은 비율(`plaus_strength`)을 쓴다.
- 확인: 실제 VLM의 실행 불가능한 결정이 규칙 기반 CF⁻보다 점수가 높게 나오는지 본다(navtest 개발 세트의 Gemma 4 31B 결정 사용). 구간마다 무작위 10개를 그려 눈으로 확인한다.

## 7. 지표

연구 질문마다 주 지표를 하나씩 두고, 나머지는 보조 지표로 함께 싣는다. 모든 지표는 시드 2개의 평균이고, 모델 사이의 차이는 같은 결정 위에서 짝지은 차이와 그 95% 구간(결정 단위로 5,000번 다시 뽑기)으로 보고한다.

| 질문 | 주 지표 | 보조 지표 |
| --- | --- | --- |
| 실행 불가능한 결정을 받았을 때 안전한가 | **D3(Gemma 4 31B)의 실행 불가능한 결정에서 불가능한 결정의 안전율** | D2에서의 같은 값, 불가능한 이유별(도로 모양 / 다른 차·보행자 / 강도) 안전율, D3 보조(Qwen3-VL 8B) |
| 그 대가로 결정을 덜 따르게 되는가 | **D1 결정–경로 일치율** | 과잉 거부율, D0 주행 점수(EPDMS) |
| 장면을 보고 판단하는가 | **결정 종류 안 AUC**(같은 결정 종류 안에서 실행 가능 / 불가능을 가르는 정도, 결정 종류마다 AUC를 내고 개수로 가중 평균) | 전체 AUC, 거부율 |
| 판단과 경로가 맞는가 (이전 Ours, Ours) | **flag–경로 불일치율**(판단은 ACCEPT인데 경로가 결정을 따르지 않거나, 판단은 REJECT인데 경로가 결정을 따른 비율) | 판단이 노이즈에 따라 흔들리는 결정이 L2의 경계 상황(채점한 후보 중 통과한 비율이 낮은 결정)에 몰려 있는가 |

- 전체 AUC는 결정 종류의 사전 확률로 맞히는 몫이 섞여 부풀려진다(규칙 기반 CF에서 전체 0.93, 결정 종류 안 0.75~0.78). 그래서 판단의 주 지표는 결정 종류 안 AUC로 한다.
- **주 비교(7.1절)의 Ours는 노이즈 1개이다.** 계산량이 B3와 같고, B3는 판단이 없어 투표할 수 없다. 노이즈 투표 효과는 따로 잰다: Ours(노이즈 1개)와 Ours(노이즈 10개 투표).
- 판단 모델의 결정–경로 일치율은 "ACCEPT이고 경로가 결정을 따른 비율"이다. 그래서 과잉 거부도 이 값에 반영된다.

### 7.1. 미리 정한 비교와 읽는 법

모든 비교는 Ours(노이즈 1개)와 상대 모델의 짝지은 차이(Ours − 상대)와 그 95% 구간으로 판정한다.

| 비교 | 보는 것 | 성공 |
| --- | --- | --- |
| Ours vs B2 | 불가능한 결정의 안전율 (D3) | 구간의 아래끝 > 0 |
| Ours vs B3 | 불가능한 결정의 안전율 (D3) | 구간의 아래끝 > −5%p (낮지 않음) |
| Ours vs B3 | D1 결정–경로 일치율 | 구간의 아래끝 > −2%p (낮지 않음) |
| Ours vs 이전 Ours | flag–경로 불일치율 (D1 ∪ D2) | 구간의 위끝 < 0 (Ours가 낮음) |
| Ours vs 이전 Ours | 결정 종류 안 AUC (D1 ∪ D2) | 보조. 값만 나란히 보고한다 |
| Ours(투표) vs Ours(노이즈 1개) | 불가능한 결정의 안전율 (D3), D1 결정–경로 일치율 | 보고만 한다(가설 없음) |

- 결과는 비교마다 **성공 / 실패 / 결론 없음**으로 읽는다. 구간 전체가 기준선의 성공 쪽이면 성공, 반대쪽이면 실패, 기준선에 걸치면 결론 없음이다(`scripts/step14_eval.py`가 판정을 함께 낸다).
- 비교는 각각 다른 질문에 답하므로 따로 판정하고, 여러 번 비교한 보정은 하지 않는다. 여러 비교를 묶은 하나의 "전체 성공"은 두지 않는다.
- Ours vs B3에서 Ours가 B3에 더해 내는 것(거부 표시와 사유)은 성공 기준이 아니라 함께 보고하는 내용이다.
- **안전율의 허용 폭을 −5%p로 둔 근거**: navtest(개발 세트)의 Gemma 4 31B 실행 불가능한 결정(94개)에서, CF 학습 구성이 다른 두 모델(12단계 C의 Ours + plausible CF⁻와 B3)의 짝지은 차이의 95% 구간 반폭을 테스트 표본 약 370개로 환산하면 약 ±4.3%p였다(구성이 같은 두 모델은 약 ±2.0%p). 14단계에서는 B3와 Ours가 구성을 각자 고르므로 앞의 경우에 가깝다. 이때 두 모델이 실제로 같으면 −3%p 기준을 통과할 확률은 약 25%, −5%p는 약 60%이다. 허용 폭은 표본 크기로 정했고, 두 모델의 navtest 차이는 보지 않았다.
- D1은 표본이 수만 개라 구간이 좁으므로(반폭 약 0.5%p) 허용 폭을 −2%p로 둔다.

## 8. 탐색 분석 규칙

- 이 문서에 없는 분석은 "탐색"으로 표시한다.
- 탐색 결과로 주 모델, 주 지표, 평가 세트, 고르는 규칙을 바꾸지 않는다.
- 탐색에서 나온 가설은 사전 등록한 뒤 처음 보는 데이터(예비 조각)에서 확인한 경우에만 주 결과로 보고한다.
- 새 모델들의 navtest(개발 세트) 결과는 새 테스트 세트의 평가가 끝난 뒤에 본다.
- 새 테스트 세트는 한 번만 평가한다. 결과를 보고 무언가를 고쳐 다시 평가하면, 그 테스트 세트도 개발 세트가 된다. 그 경우 몇 번 평가했고 무엇을 바꿨는지 그대로 보고한다.

## 9. 순서

1. 이 문서의 `[?]`를 채우고 커밋해 고정한다. (2026-10-14 완료)
2. 네트워크 볼륨을 300 GB로 늘리고 남은 24조각을 받는다. 첫 조각을 받은 뒤 실제 공간과 처리 시간을 재고 전체를 다시 추정한다.

4. 학습 데이터를 늘린다(4.1절).
5. 학습 step 수를 다시 정한다(4.2절). 이어서 장면 수 단계의 결과를 잰다(4.1절, 보고만).
6. 그럴싸함 점수를 계산한다(6절).
7. B3와 Ours의 CF 학습 구성을 각자 고른다(4.3~4.6절). Ours가 고른 구성으로 이전 Ours를 학습하고, Ours만의 설정을 고른다(5.2절: ① → ② → 노이즈 투표 m).
8. 모든 모델(B0~B3, Ours, 이전 Ours)을 시드 2개로 학습하고, 새 테스트 세트에서 한 번 평가한다.
9. 보고서: 새 테스트 결과를 주 결과로 쓰고, navtest 결과는 개발 세트 결과로 함께 싣는다.
10. 결과와 작은 산출물을 백업하고 네트워크 볼륨을 지운다(백업 목록은 `docs/TODO.md` D의 9번).
